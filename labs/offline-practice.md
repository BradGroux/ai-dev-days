# Offline practice: a reviewable plan

Use a plain-text editor, printed sheet, or partner reading aloud. No account,
network, purchase, installation, or personal data is required. This route
practices context and review; it does not demonstrate that an AI tool ran.

## Input and timing

Allow 15–20 minutes. In 5 minutes, copy this fictional note:

```text
Goal: Plan a five-stop fictional road trip in Beaver Badges.
Owner: Workshop learner.
Constraint: No purchases, accounts, location tracking, or external messages.
Output: A short plan and a decision about whether it is ready for review.
Unknown: What should happen when a visit date is missing?
```

In 5 minutes, write three clarifying questions and a plan with a goal, needed
data, one continuing-streak rule, one breaking-streak rule, and one risk.
A partner may act as the reviewer; solo learners can compare against this rubric.

## Review and expected result

Spend 5 minutes recording PASS, revise, or defer with evidence. A complete
example can say: consecutive recorded calendar dates continue a streak; a gap
breaks it; missing dates require clarification. This is a proposed exercise
rule, not an approved product requirement. Accepting that distinction and naming
the missing-date risk matters more than matching exact wording.

Save `workshop-memory.md`, `agent-plan.md` (or `workshop-goal-summary.md`), and
a decision with the reviewer, what was checked, unresolved question, and next
owner/action. Mark the method **manual/offline**, never a successful model run.

For the repair lab, deliberately remove the breaking-streak rule from a copy,
label it **seeded failure**, identify the missing rule against the contract,
write a diagnosis and patch plan, then restore it in version 2. A plan that
already passes can be accepted unchanged. Never invent a defect to finish.

## Accessibility and participation

Use text zoom, keyboard input, a screen reader, dictation, or a consenting
partner. Read the rubric aloud if useful. No learner must project their screen,
publish an artifact, share a personal story, or contribute before asking for
help. Record an accessibility limitation for the event owner if this route
still does not work; observation is participation, not proof of completion.
