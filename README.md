# AI Dev Days

Workshops, presentations, and hands-on exercises for using AI at work. Learn
with Codex and OpenClaw, from writing requirements and organizing project
context to building applications and checking the results.

The material is for developers, business analysts, educators, students, and
people who work with technology without writing code. Each event packet has
its own audience, setup instructions, exercises, and facilitator notes.

For a Codex session, start with the [Houston Business Analysts
workshop](event-specific/2026-08-19-houston-business-analysts-codex/README.md).
It includes a 27-slide deck, an attendee workbook, prompts, and a fictional
vendor-onboarding demo with staged workspaces and tests.

**Current program edition:** 2026.10.14. See the
[release notes](docs/releases/v2026.10.14.md). The previous
[edition review](docs/reviews/edition-2026-09-05.md) records the September audit
and its remaining limitations.

## What you will practice

Start with a specific problem, write down the requirements and constraints,
and try a small piece of work. Check the result against those requirements,
record what needs fixing, and leave enough context for someone to continue.

Workshops combine tool use with the work around it: deciding what to build,
understanding the available information, reviewing changes, and recognizing
when a decision needs human approval. Exercises include clear completion
checks and alternatives for attendees who cannot install or access a tool.

The curriculum maps to the U.S. Department of Labor's AI Literacy Framework:
understand AI principles, explore AI uses, direct AI effectively, evaluate
outputs, and use AI responsibly. See the [framework
alignment](docs/ai-literacy-framework-alignment.md) for sources and workshop
mapping.

## How we run sessions

- Help attendees complete a small task early, then build on it.
- Use a concrete scenario with clear requirements and a person responsible
  for reviewing the result.
- Keep source facts, assumptions, and unresolved questions distinguishable.
- Test setup and demos before the event, and prepare a fallback when a tool
  or account is unavailable.
- Keep private data, credentials, and client material out of public exercises.
- Review event feedback before changing the shared curriculum. Record what
  was accepted, deferred, or rejected and why.

## Maintaining the material

Keep event instructions, slides, and links current. Make setup short enough
for the session, check the sources behind teaching claims, and record what
worked and what needs another test. Preserve historical event packets so
attendees can find the material they used.

## Completing a workshop

A completed exercise should leave attendees with a result they can inspect,
notes on the requirements and decisions, and a clear next step. Event packets
set their own completion checks. An OpenClaw setup session, for example,
checks installation, onboarding, gateway, dashboard, and a first response.

## Project background

AI Dev Days is an independent learning community. It owns its curriculum,
events, research, governance, roadmap, and releases. OpenClaw has the most
extensive setup material in this repository; Codex workshops cover business
analysis, project context, and application development.

AI Dev Days adopts [Open Framework Commons
v2026.09.05](https://github.com/BradGroux/open-framework-commons/releases/tag/v2026.09.05)
for shared principles. The adopted version is pinned to:

- Repository: [BradGroux/open-framework-commons](https://github.com/BradGroux/open-framework-commons)
- Tag: [`v2026.09.05`](https://github.com/BradGroux/open-framework-commons/releases/tag/v2026.09.05)
