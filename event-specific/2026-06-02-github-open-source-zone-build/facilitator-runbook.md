# Facilitator Runbook

Use this as the two-day control panel for OpenClaw maintainers staffing the Open Source Zone.

## Operating Goal

Every meaningful conversation should end with one of these outcomes:

- attendee understands the OpenClaw Gateway/control-plane model
- attendee names one workflow they would safely try
- attendee scans or saves the follow-up links
- attendee is routed to OpenClaw After Hours, Discord, docs, or a maintainer follow-up

## Staffing Assumption

At least two maintainers should be ready during peak floor periods:

- one person handles the current conversation
- one person watches traffic, resets the demo, and handles quick questions

If only one maintainer is present, prioritize the 30-second hook and 2-minute overview. Do not get trapped in live troubleshooting.

## Conversation Router

Ask:

> What kind of work would you want an agent to help with if it had your real project context?

Then route:

- "Code review, issues, releases" -> maintainer demo.
- "Business operations, sales, delivery" -> business intake demo.
- "Architecture, security, local-first" -> Gateway walkthrough.
- "Can I install it?" -> attendee links and setup docs.
- "Can it run my business process?" -> explain boundary, approval, and Veritas-ready task mapping.

## Demo Decision Tree

- Less than 60 seconds: use the hook and show the architecture slide.
- 2 minutes: explain Gateway, runtime, context, tools, memory, nodes.
- 5 minutes: run the business demo or maintainer demo.
- 10 minutes: include safety model and Veritas Kanban execution framing.
- Anything unstable: switch to [fallback-plan.md](fallback-plan.md).

## Public Safety

Do not paste secrets, API keys, tokens, credentials, private attendee information, private DMs, sponsor terms, customer records, unreleased announcements, private repo data, or internal company details into the demo.

Do not connect live messaging accounts, send messages, publish content, merge code, delete data, rotate credentials, or trigger irreversible actions from the floor demo.

## Close Lines

Use one:

> The first win is not autonomy. The first win is a workflow you can see, bound, repeat, and verify.

> If you already have messy work, OpenClaw gives you a way to put context, tools, channels, and review around it.

> Veritas Kanban is the execution example: once the agent has a plan, tasks need owners, states, evidence, and review.
