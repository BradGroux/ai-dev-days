# Take one workflow with you

Choose work you actually repeat: project handoff, event planning, onboarding, research review, or weekly reporting. Use fictional or non-sensitive information during the session.

## Four-minute operating packet

- **Outcome:** What useful result should exist?
- **Owner:** Who is accountable, and who may approve consequential actions?
- **Inputs:** What sources should the tool use?
- **Procedure:** What are the smallest repeatable steps?
- **Boundary:** What must it stop and ask about?
- **Proof:** What observable check would make you accept the result?
- **Memory:** What decision, source, or next action must survive the conversation?

## Try it

Ask your tool to produce the result from your normal brief. Preserve it. Organize the same knowledge
into a requirement, a procedure, and a memory note. Run again in a fresh session. Compare against
your acceptance check, then ask a new session to continue from the saved work.

| Question | First run | With operating packet |
|---|---|---|
| Was the result correct? What proves it? | | |
| Did it handle a missing fact or exception? | | |
| What did I have to explain again? | | |
| Could someone else continue? | | |

Keep the useful procedure and accepted lessons. Adjust the packet if both runs fail. A better-looking answer is not enough.
