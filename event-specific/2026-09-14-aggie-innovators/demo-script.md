# Aggie Launchpad demo script

Use [shared prompts](demo/prompts.json) and the [presenter console](demo/index.html). All research data is fictional. The 90-minute presentation flow remains unchanged.

## Introduce the venture
Jordan wants to test Campus Cycle, bicycle-repair pickup for students. Show the distinction between 20 interviews, 12 expressions of interest, and six free-pilot reservations. The target is five active reservations for a founder review. Paid demand is untested.

## First run: raw brief
Prepare an isolated workspace with venture-brief.md only. Run the shared build prompt in Codex, then the shared Buzz review. Save the actual output and handoff. Do not assume this condition will fail. Inspect against the same acceptance criteria used for the second run.

## Teach the framework
Show how requirements define output, the procedure defines handling of changed evidence, and memory preserves decisions and learning. The operating packet organizes facts already in the raw brief; it is not a source of hidden market information.

## Second run: operating packet
Use a fresh workspace with the identical source plus requirements, procedure, memory, and context-loading instructions. Match model/settings, time allowance, tool permissions, and build prompt. Record inherited account/global context if it cannot be removed.

## Apply the same change to both
Read update U-01: P05 and P06 canceled. Inspect four active reservations against five required. Reapply the update to check it is not counted twice. Neither interview interest nor a lowered target can replace the missing reservation. Jordan decides recruit/revise/pause; the agent cannot invent that decision.

## Continue in Buzz
Give a fresh context the saved artifacts and the continuation prompt. Can it explain observations, assumptions, changes, source IDs, target, and next owner? Record the result and any corrections.

## Compare and discuss
Use the eight-criterion rubric, with actual evidence and timestamps. Show outputs at equal scale. Count substantive manual corrections and identify what context carried forward. A visually polished dashboard alone is not evidence of a better operating process. The reference mockup is illustrative, never presented as model output.

Actual paired builds, recordings, and scoring remain to be rehearsed. No real customers, payments, bookings, outreach, or publication are part of this demo.
