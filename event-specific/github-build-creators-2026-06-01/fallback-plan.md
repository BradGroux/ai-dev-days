# Fallback Plan

Use this if screen sharing, network, model access, or live generation fails.

## If Slides Fail

Use [`slides.pdf`](slides.pdf) or [`slides.pptx`](slides.pptx). If both fail, use this talk track:

1. OpenClaw gives agents durable context, bounded access, and visible workflow.
2. Creators can use that for research, outlines, recap posts, clip plans, sponsor-safe drafts, and community follow-up.
3. The safe operating pattern is context, role, boundary, artifact, verification.
4. The demo is draft-only. No private data, no live publishing.
5. Join the SSTB Discord for office hours and follow-up material.

## If OpenClaw Fails

Do not troubleshoot live for more than 30 seconds. Say:

> The setup is not the lesson. The workflow pattern is the lesson.

Then walk through [`prompt-pack.md`](prompt-pack.md) as a prompt-read demo:

1. Show the memory starter.
2. Explain why the boundary exists.
3. Read the Content Planner prompt.
4. Read the Safety Reviewer prompt.
5. Read the Verification Reviewer prompt.

## If Network Fails

- Use the local PDF or PPTX.
- Use a staged text output if available.
- Point to the repo and Discord verbally.

## If Time Is Cut To 5 Minutes

Use only these slides:

1. Intro
2. Why OpenClaw
3. Architecture in 60 seconds
4. Demo SOP
5. Build week schedule

Close with:

> Do not start by asking for content. Start by writing the context, defining the boundary, choosing the role, and verifying the output.
