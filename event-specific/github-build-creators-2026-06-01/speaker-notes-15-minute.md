# Speaker Notes - 10 To 15 Minute Creator Demo

## Opening

Use a practical tone. This audience does not need a long AI primer.

Core line:

> OpenClaw is not just another chat box. It is a local-first control plane for giving agents durable context, bounded access, and a visible workflow.

Safety line:

> The demo uses sanitized examples. Do not paste secrets, private DMs, sponsor contracts, customer records, API keys, or unreleased business details into public tools.

## 0:00-1:00 - Intro

- Brad Groux, Digital Meld.
- OpenClaw maintainer.
- Focus today: what OpenClaw makes possible for creators, not a full install walkthrough.
- Point to the Discord QR on the intro slide for follow-up questions and office hours.

## 1:00-3:00 - What OpenClaw Is

OpenClaw is easiest to explain as a local-first control plane for useful AI agents.

Plain-English model:

- Gateway routes work from clients, channels, nodes, and automations.
- Agent runtime assembles context, talks to models, calls tools, streams progress, and persists state.
- Workspace files, memory, skills, tools, and session history become durable context.

Avoid over-explaining architecture. Creators should leave with the point:

> Your agent gets better when it can see the right context, use the right tools, and show its work.

## 3:00-4:30 - Why Creators Should Care

Use creator examples:

- turn a messy idea dump into a segment outline
- convert a conference note into a post, clip brief, and follow-up thread
- research a guest without losing the source trail
- draft sponsor-safe language while keeping private terms out of the tool
- prepare community replies without letting the agent post on its own

Key distinction:

> The win is not faster generic content. The win is a workflow you can inspect, reuse, and improve.

## 4:30-8:30 - Live Demo

Use [`demo-script.md`](demo-script.md). Recommended path: creator conference recap.

Demo beats:

1. Start with the workflow, not the model.
2. Open the checked-in memory, PRD, and SOP demo files.
3. Ask the agent to clarify before drafting.
4. Run the Content Planner role.
5. Run the Safety Reviewer role.
6. Run the Verification Reviewer role.
7. Show the draft or fallback output and point out what still requires human judgment.

Do not chase tool setup if something is slow. Use the fallback plan and narrate the pattern.

## 8:30-10:00 - Close

Close with three points:

1. OpenClaw helps agents work with context, access, and integrations.
2. Good agent work has boundaries and verification.
3. Join the Discord for follow-up, office hours, and Dev Days material.

Then show the Build week schedule slide.

## Optional 10:00-15:00 - If Time Expands

Use this order:

1. Ask the room what creator workflow they would automate first.
2. Apply the same pattern: context, role, boundary, artifact, verification.
3. Name one thing not to automate without approval.
4. Invite people to OpenClaw After Hours at GitHub on Wednesday, June 3, 2026.

## Hard Stop Line

> If you remember one thing: do not start by asking for content. Start by writing the context, defining the boundary, choosing the role, and verifying the output.
