# Example Memory: Vendor-Onboarding Context

> Teaching artifact: this file demonstrates useful recall. It is not Codex's
> generated local memory store, not approved policy, and not an authority for a
> vendor decision. Required rules belong in `AGENTS.md`, policy, and approved
> documentation.

## Useful background

- The workshop audience is learning how business analysis artifacts become
  durable agent context.
- The demo should stay business-readable and avoid spending time on terminal
  mechanics.
- Vendor onboarding was chosen because it crosses Procurement, Finance,
  Security, Legal, Compliance, and requester handoffs.
- Prior rehearsals found that people often misread PASS as approval. Always say
  “ready for human review.”

## Helpful presentation choices

- Show filenames before implementation details.
- Ask “Who owns that decision?” when an approval is implied.
- Ask “What would prove that?” when the room jumps to automation.
- Use V-002 to teach that `unknown` is not `no`.
- Use V-003 to teach that urgency cannot erase a stop condition.

## Authority warning

If this file conflicts with approved policy, `AGENTS.md`, the SOP, the PRD, or
the data contract, ignore this file and surface the conflict. Do not move a rule
here merely because it is convenient to remember.
