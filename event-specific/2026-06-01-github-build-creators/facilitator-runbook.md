# Facilitator Runbook

Use this as the one-page control panel for the June 1, 2026 GitHub Build creator pre-day demo.

## Room goal

Give a technical creator audience a quick, concrete picture of OpenClaw:

- what it is
- why context, access, integrations, and verification matter
- how a creator workflow becomes an agent workflow
- where to continue the conversation during Build week

## Presenter stance

Keep it practical. This is not a full workshop, a product pitch, or an install clinic.

Core line:

> OpenClaw is not just another chat box. It is a local-first control plane for giving agents durable context, bounded access, and a visible workflow.

## Live demo path

Use [`demo-script.md`](demo-script.md).

1. Open the memory file.
2. Ask for clarifying questions.
3. Run the Content Planner.
4. Run the Safety Reviewer.
5. Draft one artifact.
6. Run the Verification Reviewer.

If the live demo slows down, switch immediately to [`fallback-plan.md`](fallback-plan.md).

If the room is asking business-ops questions, switch to the optional
[`business-use-case-quick-demo.md`](business-use-case-quick-demo.md) path.

## Public safety

Do not paste secrets, API keys, tokens, credentials, private DMs, sponsor terms, attendee contact data, customer records, unreleased announcements, or private operational details into the demo.

Do not connect live social accounts, send messages, publish content, or expose private OpenClaw workspace files.
