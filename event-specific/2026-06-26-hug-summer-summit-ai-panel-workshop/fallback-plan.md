# Fallback Plan

Use this if time, setup, network, or provider configuration starts consuming
the room.

## Rule

Protect momentum. If a blocker takes more than 10 minutes, move the attendee
to observe, pair, or use the presenter demo path.

## If Solo Presentation Time Shrinks

- Use slides 1-5 for the AI foundation.
- Use slide 8 for OpenClaw.
- Use slides 10-13 for memory, agents, channels, and the agent harness.
- Use slides 16-17 for the workshop handoff.

## If Wi-Fi Is Unreliable

- Keep the presenter machine connected if possible.
- Move attendees into observation mode.
- Use the slide deck, prompt pack, and demo script.
- Focus on concepts: context, memory, instructions, review, and human judgment.

## If Installs Fail

- Put the attendee in the red lane.
- Pair them with someone already running.
- Use the presenter machine for the live demo.
- Revisit their machine after the main flow.

## If Model Provider Setup Fails

- Confirm provider, endpoint, key, deployment name, and model name.
- If it still fails, stop debugging in front of the whole room.
- Move to the prompt-only research-agent exercise.

## Minimum Viable Outcome

Even if setup fails, attendees should leave with:

- a clear difference between AI, chatbots, and agentic AI,
- a safe first workflow idea,
- a Markdown memory file,
- an `AGENTS.md` instruction file,
- a research-agent prompt,
- a review prompt before trusting the output,
- one channel boundary for where reviewed output may go.

## Safety

Do not put secrets, API keys, tokens, credentials, private student data,
donor data, staff records, confidential notes, or anything sensitive into
public repositories, shared files, screenshots, or projected prompts.
