## Decision and provenance

Adopt Open Framework Commons **v2026.09.05** independently, without deviations:

- Repository: [Open Framework Commons](https://github.com/BradGroux/open-framework-commons)
- Annotated tag object: `67914a6e305768206f1ead83dfcbc4325b951168`
- Peeled commit: `8868a248457dd7b663563beb243c5ebcbb8ac360`
- Verification: authenticated GitHub ref/tag API and Git remote advertisement
  agreed with the local objects on 2026-09-05.

Reviewed at that commit: principles, boundaries, governance, research/review,
Decision 0002, adverse content cases, audit disposition and release procedure.
Their human boundaries and evidence limits fit our existing independent charter.
Help need not be earned; prior contribution buys no participation or publication
rights; stopping and privacy can take priority over continued participation.
These are chosen commitments, not empirical claims that the program is effective.

Affected guidance is the charter, governance, research method, contribution
instructions, active navigation, reusable curriculum and facilitator runbook.
Bounded conflict handling now pauses the disputed action, uses the exact adopted
revision, and records a responsible authority and reasoned disposition. A new
Commons edition or silence does not grant permission.

Commons' own CI, dependency stack, committees, interfaces and review artifacts
are not imported as program requirements. Its five-product scope does not turn
AI Dev Days into a child product. No other repository is changed. Retaining the
old pin was a valid alternative, but would leave useful explicit help/consent
boundaries outside current adoption. No substantive conflict or deviation was
identified in the reviewed local guidance. Practitioner and learner evidence
remain limited; fictional cases test interpretation only.

## Independent identities and compatibility

Program/content editions now use YYYY.MM.DD and annotated vYYYY.MM.DD tags,
based on actual UTC publication date. Additional same-day releases use .1, .2,
and so on. Never retag or add dated aliases to old editions. The existing
v1.0.0/v1.1.0 decisions, citations, tags, releases and event-folder names retain
their historical meanings. Date ordering is chronological, with correction
suffixes compared numerically; the date does not promise compatibility.

This is substantive guidance correction: readers must reconsider the idea that
local files are private from a cloud provider, that a successful review needs
an invented failure, or that submitted data is independently confirmed.
Offline practice and storage recovery are compatible additions. Research
transcript republication is withdrawn from the current edition because a rights
basis is not recorded; source links and historical commits are preserved.

The optional AI-Native teaching baseline remains v1.0.0, annotated tag
`30f03a60079ed37432f9dc30aadd1a71c1e22365`, commit
`ebf41b037720452fe7bea652cad29516d5b95339`, verified separately through GitHub
and inspected against the six concerns and local teaching mapping. It does not
advance automatically with Commons. No empirical compatibility certification
is implied. Beaver Badges retains package 0.0.1 and storage schema/key v1;
no package parser consumes the program edition.

## Historical limit and reconsideration

The historical local AI Dev Days v1.0.0 tag object differs from GitHub after
previous authorized republication documented in earlier issues/decisions.
Neither object is overwritten in this task. The release runbook records both
identities and verification limits. Immutable identities apply prospectively.

Revisit this decision when learner feedback reveals exclusion or disclosure,
when a selected tool changes its workspace/provider boundary, or when new
Commons/AI-Native guidance warrants a separate local review. The program
maintainer owns the disposition; no universal effectiveness claim is approved.
